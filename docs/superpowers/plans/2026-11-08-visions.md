# Visions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Global, nestable visions above goals, with their own view, a map band, a contribution glow across all
views, and a gold Purpose.

**Architecture:** A new `js/visions.js` (loaded after sync.js, before drive.js/app.js) owns the global vision
store (`actionplan.visions`), its change stamps, its merge, and the pure rules (loops, reached, contributing set,
Purpose). Goals keep their links in `goal.visions`. app.js gets the view, forms, map band and glow classes;
drive.js carries the store in the Drive file.

**Tech Stack:** vanilla JS, SVG, CSS; tests in headless Chrome (`bash tests/run.sh`).

**Spec:** `docs/superpowers/specs/2026-11-08-visions-design.md`

## Global Constraints
- EN + SL for every new string (`js/i18n.js`); key parity test must pass.
- No tour steps, help banners, ⓘ tips, sample-plan or template content for visions (user decision).
- Help mode in the Visions view must not show a raw key: the banner is skipped when a view has no help text.
- Only goals link to visions. Vision parents: any number, no loops.
- `js/visions.js` added to `index.html`, `sw.js` cache list and `tests/run.sh` copies (it copies `js/` whole).
- Repo files are LF; edit with the Edit tool (no `sed -i`).

## Review Focus
- A vision deleted while goals in other plans still link to it: no errors, links ignored, Purpose unaffected.
- Two devices adding parents that together form a loop: merge drops one, rules never recurse forever.
- Purpose with paused/achieved goals only (no active goal): not Purpose.
- Switching plans or syncing changes Purpose: glow/gold/logo follow without a reload.
- Old Drive files and old localStorage without `visions`: load as empty, no crash.

### Task 1: Vision store and rules (`js/visions.js`)

**Produces:**
- `visions` – `{ list, deleted, purposeFound }`; `loadVisions()`, `saveVisions()` (stamps `updatedAt`,
  tombstones, writes localStorage, bumps `visionsVersion`, calls `scheduleSync()` if defined).
- `findVision(id)`, `visionParents(v)` (existing ids only), `visionRoots()`, `visionReaches(from, to)`,
  `canParent(childId, parentId) -> null | errorKey`, `visionChildren(id)`.
- `goalVisionIds(g, goals)`, `allPlansGoals()` → `[{ planId, goals }]` (current plan from `db`),
  `reachedVisions() -> Set`, `contributingIds(data = db) -> Set`, `purposeState() -> { on, root, roots, unlinked: [{planId, goal}] }`
  (cached on `visionsVersion` + a plan-data version bumped by `save()`/sync).
- `deleteVision(id)` removes it and drops it from other visions' parents.

  ancestor, contributing set (sub-goal, contributes activity + its sub-activity, measuring state, improving
