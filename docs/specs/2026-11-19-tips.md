# Tips: design

Builds `docs/guidance/03-tips.md` (what the user sees, rules, catalogue, texts, tests). This file
only records what differs from that plan, the data shape, the modules and the order of work.
Status: **draft, waiting for the owner** (decision 7 and the questions below).

## Questions for the owner

1. **Guidance decision 7**: tips on by default, at most one a day, none while Getting started's
   first stage is open. Confirm, or choose off by default.
2. **Two sessions**, each shippable (below). Or one session, as with Getting started.
3. **Dates the plan does not hold.** Some tips need to know *since when* something is true:
   `stuck-step` (In progress since), `waiting` (waiting since), `achieved` (achieved on),
   `halfway` (was under 40 % once). Items only carry `createdAt` (goals, activities, visions) and
   `updatedAt` (any change). Proposal: the tips record the first day they saw each fact
   (`tips.since`, below), on this device. A tip can then fire only 21 days after the app first
   saw the step In progress; on the first day of tips, an old stuck step is not caught at once.
   Alternative: use `updatedAt` as "since" (fires sooner, but any edit, even a typo fix,
   resets it).
4. **`goal-unfinished`** (from `06-goal-form`, class B, cooldown 30 days) joins the catalogue.

## Changes to the plan

- **Views and days are recorded whenever tips are on**, not only while Getting started is on
  (`markView` for map, timeline, graphs; `markDay`). `try-*`, `install`, `first-month` need them.
- **New `seen` facts**: `menu` (context menu used once), `templates` (templates dialog opened).
- `backup` treats "logged in with Drive sync on" or `seen.exported` as backed up.

## Data shape

- Preference `tips` (per user, per device, not synced; decision 5):
  `{ off?: boolean, day?: ISODate, current?: string | null, shown: { [key]: { n, last, closed?, snoozed? } }, since: { [fact]: ISODate } }`.
  Missing or broken reads as defaults (`off` false, empty maps). Saves merge with what is
  stored (`closed` and the larger `n` win), so a second tab never undoes a ×.
  `since` keys: `doing:<activityId>`, `waiting:<activityId>`, `achieved:<goalId>`,
  `under40:<goalId>`; dropped when the fact stops being true or the item is gone.
- Preference `seen` gains `menu?: true`, `templates?: true`. Unknown facts kept as today.
- No plan data, sync file or export changes; no fixture needed.

## Modules

| Module | What |
|---|---|
| `core/guidance/tip-limits.ts` | every threshold as a named constant, for the owner to tune |
| `core/guidance/tip-facts.ts` | shared pure facts: last activity, kept share, overdue list, goal pace |
| `core/guidance/tips-a.ts`, `tips-b.ts`, `tips-cd.ts` | the catalogue by class: `{ id, cls, view, cooldown, guide?, when(input) → item \| true \| null, action }` |
| `core/guidance/tip-choice.ts` | blocks, history rules, the choice, one-a-day, `since` upkeep |
| `store/tips.ts` | read, merge and write the `tips` preference |
| `tutorial/tips.ts` | the card on the Overview and its view, buttons, settings hint; via `onRendered` |
| `ui/settings.ts` | Display › Tips switch |
| `i18n/en.ts`, `sl.ts` | `tip.*`, `settings.tips` |
| `i18n/guide.en.ts`, `guide.sl.ts` | article `tips-all` in Start here |

Actions are names (`openTimeline`, `editItem`, `addActivityFor`, …) resolved in
`tutorial/tips.ts`, so `core/` stays free of page code.

## Sessions

- **A. The engine and the struggling tips.** Limits, facts, choice and history, `store/tips.ts`,
  the card, the Settings switch, classes A and B (with `goal-unfinished`), `since` recording.
- **B. Praise and discovery.** Classes C and D, the new `seen` facts and recording, `tips-all`.

## Tests

As in the plan's "Test cases", unit tests first: each tip just true and just false at every
threshold; choice order; history (cooldown edges, third showing, ×, Not now, once-only);
one-a-day; blocks; period tips and date edges; `since` upkeep and merge of two tabs. Page
steps in `tests/browser/tips.js`: card on Overview and on its view, action, Why this helps,
Not now and × after reload, Settings switch, hint on the first three only, escaping and a long
title, deleted item, 360 px. Speed: `npm run perf` on the large plan.
