# Journal store (feature 00 part 1, WP-008)

What: `docs/features/00-foundation.md` part 1, with the owner's choices at its end. No screen.

## Data shape

As in the feature file: `{ reviews: [], sessions: [], focus?, deleted: {} }`. Local key
`actionplan.journal` (through `userStorage`, so per user). Absent until something is saved, so
a device without a journal writes no `journal` section and older fixtures stay as they are.

## Modules

- `core/journal.ts` (new, pure): types, `normalizeJournal`, `mergeJournal`.
- `core/merge.ts`: `stampList` (the stamping `saveVisions` does), shared by visions and journal;
  `Store.journal?`; `mergeStores` merges it.
- `store/journal.ts` (new): load, save, the add/update/delete API, focus, another tab's change.
- `store/visions.ts`: `saveVisions` uses `stampList`.
- `store/plans.ts`: `load()` loads the journal too (so `enterUser` resets it).
- `sync/drive.ts`: `SYNC_VERSION = 3`; `parseStore` and `toFile` carry `journal`.
- `sync/sync.ts`: `localStore`, `dropStarterPlans`, `applyStore` carry it.
- `ui/plan-io.ts`: the backup includes it (stays `version: 1`); restore merges it.
- `main.ts`: the `storage` listener for another tab.
- `scripts/fixtures.mjs`: sync files of version 1 or 2 match a version 3 output; new storage
  fixture `journal`.

## Tests

Unit: `normalizeJournal` (empty, missing, wrong types, bad ids, unknown fields kept);
`mergeJournal` (newer wins, deletion after change removes, change after deletion survives,
symmetric, two reviews for one period both kept, focus by later `at`, one side missing);
`stampList`; `parseStore`/`toFile` keep the journal; version 4 file gives `update`; store API
saves, stamps, tombstones, storage full emits `storageError`.
Page: per-user separation; sync up and down with the fake Drive; backup and restore merge.
Fixture: `journal` storage round trip.
